# Публикация проекта на GitHub

Этот документ — чек-лист сопровождающего: что уже подготовлено в репозитории,
что осталось сделать человеку и какие решения принять.

## Что уже сделано

- `LICENSE` — MIT для кода + список сторонних компонентов и моделей с их
  лицензиями: GigaAM v3 (MIT), sherpa-onnx (Apache-2.0),
  pyannote/segmentation-3.0 (MIT), NVIDIA TitaNet (CC-BY-4.0), FFmpeg
  (LGPL/GPL, внешний процесс), библиотеки интерфейса.
- Раздел «Лицензии» в `README.md` — та же таблица с атрибуцией.
- Экран «Помощь» в приложении уже упоминает технологии и лицензии.

**Метаданные пакета** (`pyproject.toml`)

- `[project.urls]` — Homepage / Repository / Issues / Changelog.
- `[tool.setuptools.package-data]` — `nestor/web/static/*` попадает в wheel
  (проверено сборкой: `index.html` внутри `.whl`).
- `nestor --version` печатает версию.

**Документация репозитория**

- `README.md` — исправлена версия установщика (1.3.7), ссылка на установку,
  раздел лицензий.
- `SECURITY.md` — как сообщить об уязвимости, что считается уязвимостью,
  описание модели безопасности (loopback, сеансовый токен, офлайн).
- `CONTRIBUTING.md` — окружение, тесты, запуск, стиль, порядок PR.
- `CHANGELOG.md` — указатель на `docs/README-releases.md`.

**GitHub-обвязка**

- `.github/workflows/ci.yml` — `pytest` на `windows-latest` и `ubuntu-latest`
  (Python 3.12).
- `.github/ISSUE_TEMPLATE/` — формы баг-репорта и предложения,
  `config.yml` с ссылками на руководство и безопасность.
- `.github/PULL_REQUEST_TEMPLATE.md`.
- `.gitattributes` — бинарные типы помечены, переводы строк не портятся.

**Гигиена репозитория**

- `.gitignore`: `opencode.json` (локальный MCP-конфиг) и `_publish_internal/`.
- `opencode.json` снят с отслеживания (файл остался на диске).
- Внутренние материалы вынесены в `_publish_internal/` (не под git):
  «Замеры производительности 1.3.1.docx», «Инструкция тестировщику —
  i5-1235U.md», «Тест-кейс — Nestor 1.3.7.md». В них есть названия
  заказчиков и внутренняя информация.
- `samples/` игнорируется и **никогда не попадал в историю** (проверено:
  клиентская запись «Встреча ИТ-ИБ 31.03.webm» в коммитах отсутствует).

**Надёжность**

- Исправлена гонка при завершении задания: `timings.json` / `stage_seconds`
  теперь записываются **до** сохранения статуса `done`, поэтому наблюдатель,
  увидевший «done», уже видит разбивку по стадиям. Раньше тест
  `test_timings_written_after_job` падал примерно 1 раз из 5 (после правки —
  6 прогонов подряд без падений).

## Что нужно сделать человеку

GitHub CLI установлен в `%TEMP%\ghcli\bin\gh.exe` (winget на машине нет).
Авторизации нет — она требует вашего входа.

1. Войти в GitHub (один раз, в браузере):

   ```powershell
   & "$env:TEMP\ghcli\bin\gh.exe" auth login
   ```

2. Создать репозиторий и запушить `master` (подставьте владельца; `--public`
   или `--private`):

   ```powershell
   gh repo create AndroDaemon/Nestor --source . --public --push `
     --description "Offline transcription and speaker diarization for Russian audio on CPU"
   ```

   Если репозиторий уже создан вручную:

   ```powershell
   git remote add origin https://github.com/AndroDaemon/Nestor.git
   git push -u origin master
   ```

3. Поставить тег версии и приложить установщик:

   ```powershell
   git tag -a v1.3.7 -m "Nestor 1.3.7"
   git push origin v1.3.7
   gh release create v1.3.7 "packaging/output/Nestor-Setup-1.3.7.exe" `
     --title "Nestor 1.3.7" --notes-file docs/release-notes-1.3.7.md
   ```

   Onedir-сборку `dist/Nestor/` целиком в git не кладём (≈1.6 ГБ) — она
   распространяется через Release, а не через репозиторий.

4. Заменить плейсхолдеры `AndroDaemon` перед публикацией:

   ```powershell
   (Get-ChildItem -Recurse -Include *.md,*.yml,*.toml `
     | Select-String -Pattern 'AndroDaemon' -List).Path
   ```

## Брендинг — нейтральный

Палитра интерфейса (чёрный / белый / маджента / электрик-блю) сохранена как
есть, но все сторонние текстовые метки, бейджи и логотипы из приложения и
документации убраны: интерфейс не ссылается на какой-либо бренд или
организацию.

Папка `docs/presentation/` удалена из репозитория.

**История.** Публикация начинается с **чистой истории** — один коммит с
текущим состоянием, без прежних коммитов. Так на GitHub не попадает ни один
ранний файл с упоминанием бренда. Файлы с реальными записями и клиентскими
документами в историю не попадали и раньше.

## Юридическая заметка по моделям

Веса моделей не хранятся в git: в dev-режиме они скачиваются при первом
запуске (`nestor models`), в поставку попадают через установщик. Атрибуция
выше обязательна для CC-BY-4.0 (TitaNet) и достаточна для остальных.
pyannote/segmentation-3.0 формально требует принятия условий на Hugging Face
при скачивании — распространение самих весов в составе установщика стоит
перепроверить перед публичным релизом.
