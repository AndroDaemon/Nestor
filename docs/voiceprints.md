# Голоса (voiceprints) — локальная идентификация спикеров

Статус: реализовано и проверено (58 passed, 1 skipped; живые проверки API+UI пройдены).
Ветка: master. Версия 1.1.9 в `nestor/__init__.py` и `MyAppVersion` в `packaging/Nestor.iss`.

## Что это
После диаризации Nestor сравнивает голосовые отпечатки кластеров с локальной
библиотекой и подставляет знакомые имена. Незнакомые остаются `SPEAKER_NN`.
Всё офлайн, на CPU, без сети. Модель — тот же TitaNet-small
(`nemo_en_titanet_small.onnx`), что уже используется диаризацией.

## Правило узнавания (все три условия обязательны)
1. косинусная близость к лучшему голосу ≥ 0.75 (до 1.1.0 — 0.65);
2. отрыв от второго кандидата ≥ 0.05 (нет «ничьей»);
3. ≥ 60% сегментов кластера голосуют за того же победителя (короткие
   сегменты < 0.5 с не голосуют). При < 5 сегментов — округление вверх
   (2 сегмента требуют 2 голоса).
Один голос не присваивается двум спикерам. Не прошло — остаётся `SPEAKER_NN`.

## Хранение (только этот компьютер)
```
%LOCALAPPDATA%\Nestor\
  voiceprints\<slug>.npy      вектор float32 (dim 192, L2-нормализован)
  voiceprints\voiceprints.json  метаданные (schema_version=2)
  embeddings\<record_id>.npz  кэш эмбеддингов записи (для «запомнить голос»)
```
Запись атомарная (tmp + os.replace с ретраями). Повторное «запоминание» того
же имени усредняет вектор по длительностям (running average), а не затирает;
если длительность одной из сторон неизвестна (0, напр. голос из чужого файла
без метрики) — стороны перемешиваются поровну, никогда не заменяя старый портрет.
Slug — транслитерация имени («Иван Петров» → `ivan-petrov`), коллизии → `-2`.

## Модули
- `nestor/voiceprints.py` — `VoiceprintLibrary` (add_or_update/list/delete/find/save/load)
- `nestor/speaker_embed.py` — обёртка над `sherpa_onnx.SpeakerEmbeddingExtractor`,
  кластерные и посегментные векторы, кэш npz
- `nestor/speaker_match.py` — `match_clusters`, `MatchThresholds`, `MatchResult`
- интеграция: `pipeline.py` (стадия «распознавание голосов», полоса 0.95–0.98),
  `web/app.py` (эндпоинты, speaker_match в record.json), `cli.py`

## Как пользоваться
- UI: навести на ярлык спикера в записи → кнопка 🎙 «запомнить голос»
  (имя берётся из поля ярлыка). Панель «Голоса» — кнопка внизу главного экрана.
  Тумблер «подставлять знакомые имена» и слайдеры порогов — в настройках
  на главном экране.
- Web API: `GET/POST /api/voiceprints`, `DELETE /api/voiceprints/{slug}`
  (POST: `{name, recording_id, speaker}`).
- CLI:
  - `nestor voiceprints list | remove <имя> | recordings`
  - `nestor voiceprints add <имя> --from-recording <id> --speaker SPEAKER_00`
  - `nestor voiceprints add <имя> --from-audio file.wav`
  - `nestor transcribe ... --match-voiceprints / --no-match-voiceprints`
  - строка результата: `[voiceprints] SPEAKER_00 -> Иван (0.81), ...`

## Гарантии совместимости
- Дефолтный `Config` (матчинг выключен, кэш выключен) → поведение и файлы
  как в 1.0.0 (регресс-тест байт-в-байт).
- В web кэш эмбеддингов включён всегда — «запомнить голос» по записи,
  обработанной этой версией, мгновенно (из npz); по старым записям —
  расшифровка-фолбэк с пересчётом эмбеддингов.
- Ручное переименование спикера всегда перекрывает автораспознанное имя.
- Экспорты json/srt/vtt/txt/md/docx не изменены: имена подставляются
  существующим слоем `speaker_names`, `segment.speaker` остаётся `SPEAKER_NN`.

## Замечания по настройке порогов
Дефолт 0.75 (с 1.1.0; ранее 0.65, подобран по smoke-тесту: соседние окна одного
файла дают 0.64–0.99, разные голоса ниже). На реальных записях с шумом может
понадобиться подстройка;
слайдеры в настройках существуют для этой подстройки. Матчинг работает только
при включённой диаризации (backend «без диаризации» = один спикер без матча).
