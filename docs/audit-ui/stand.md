# Стенд для аудита UI/UX — Nestor 1.5.3

Цель: аудитор открывает работающее приложение и проходит чек-лист по живым
экранам. Ниже три способа поднять стенд — от самого простого к «как у
разработчика».

> Единый контекст: приложение хранит все данные в `%LOCALAPPDATA%\Nestor`
> и нарочно **не запускает второй экземпляр** — повторный запуск поднимает
> уже открытое окно. Перед запуском закройте другие копии Nestor.

---

## Способ 1. Установщик (обычный путь пользователя)

Файл: `packaging\output\Nestor-Setup-1.5.4.exe` (≈264 МБ, версия 1.5.4).

1. Запустить `Nestor-Setup-1.5.4.exe`. Ставится в `%LOCALAPPDATA%\Nestor`
   **без прав администратора**.
2. Отметить по желанию ярлык на рабочем столе, «Установить».
3. Запустить Nestor (ярлык или `%LOCALAPPDATA%\Nestor\Nestor.exe`).
4. Откроется окно (Microsoft Edge WebView2 — есть на Windows 10/11 из коробки).

Плюс этого пути: аудитор видит **ровно то, что увидит пользователь**,
включая первый запуск, установку и ярлыки. Хорошо для оценки онбординга.

Минус: установка занимает место и пишет в `%LOCALAPPDATA%`.

---

## Способ 2. Портативная сборка (быстро, без установки)

Готовая onedir-сборка лежит в репозитории: `dist\Nestor\` (≈0,5 ГБ).

1. Открыть папку `dist\Nestor\`.
2. Запустить `Nestor.exe` (двойной клик).

Важно: это **onedir**-сборка PyInstaller — `Nestor.exe` нельзя отделять от
своей папки `dist\Nestor\` (рядом лежат `_internal\models` с моделями —
поэтому приложение работает полностью офлайн).

Данные всё равно пишутся в `%LOCALAPPDATA%\Nestor` (общая библиотека с
установленной версией), а не рядом с exe — учитывайте это, если на машине
уже стоит Nestor: обе копии работают с одной библиотекой.

---

## Способ 3. Из исходников (для аудита вёрстки, без сборки)

Нужен Python ≥ 3.10 и окружение проекта (`.venv`).

```bat
cd C:\OpenCode\Nestor
.venv\Scripts\activate
nestor desktop          :: окно приложения из исходников
:: или
nestor serve            :: тот же интерфейс в браузере, http://127.0.0.1:8000/?token=...
```

Плюс: правки `nestor/web/static/index.html` видны сразу после **Ctrl+R**
в окне — удобно, если аудит переходит в правки и повторные проверки.
Пересборка exe не нужна.

Для браузера адрес печатается в консоли вместе с сессионным токеном
(сервер слушает только `127.0.0.1` и требует токен).

## Демо-данные

### Простые сэмплы (в репозитории, `samples\`)

| Файл | Что это |
|---|---|
| `dialogue.webm` / `dialogue.mp3` | короткий диалог **двух голосов** (синтез Edge TTS) — идеален для проверки панели спикеров и склейки |
| `example.wav` | короткий пример |
| `long_example.wav` | подлиннее, для прогресс-бара |
| `22.10.26.webm` и др. | реальные многочасовые записи (см. ниже) |

Чтобы получить готовый результат в приложении, на **главном экране**
перетащите файл в дропзону и дождитесь обработки (короткий диалог — меньше
минуты).

### Готовая библиотека (если её разрешено показывать)

На этой машине в `%LOCALAPPDATA%\Nestor` уже лежат **пять полностью
распознанных записей** — удобно для аудита шита на «настоящем» объёме:

| Запись | Длительность | Реплик | Спикеров |
|---|---|---|---|
| `22.10.26.webm` | 1 ч 13 мин | 845 | 68 |
| Мультипасс.webm | 40 мин | 316 | 19 |
| Мультипасс… Mobile ID T2 | 52 мин | 473 | 23 |
| Встреча ИТ-ИБ 31.03.webm | 1 ч 01 мин | 370 | 16 |
| Босфор.webm | 31 мин | 292 | 13 |

> Внимание: это **реальные рабочие записи** (совещания), а не синтетика.
> Прежде чем передавать стенд внешнему аудитору, убедитесь, что их показ
> допустим. Для обезличенного аудита используйте `samples\dialogue.*` и
> любую пару коротких сэмплов.

### Как получить состояние «в работе» и «ошибка»

- **В работе**: поставьте на обработку `samples\22.10.26.webm` (2 мин) или
  любую длинную запись и не дожидайтесь — смотрите рейл, процент, ETA.
- **Ошибка**: специально ломать ничего не нужно; если нужно показать вид
  ошибки, подойдёт любое состояние, которое уже есть в библиотеке, либо
  воспроизведение прерванного прогона (закрыть приложение во время
  обработки, затем открыть — запись останется «в работе» и будет сброшена
  в «остановлено» при старте).

## Что показать аудитору в первую очередь

1. Главный экран целиком (настройки, дропзона).
2. Пустую библиотеку и библиотеку с пятью записями.
3. Шит на длинной записи: 845 реплик, 68 спикеров — панель спикеров,
   группа «Фон», счётчик «узнал X из Y спикеров».
4. Док плеера: волна, перемотка, фильтр по спикеру, соло-проигрывание.
5. Модалки: «От чего зависит результат», «Приватность…», «Голоса», «Словарь».
6. Диалог повторного прохода (правый клик по записи → «Распознать спикеров
   заново» / «Обработать заново»).

## Техническая справка

- Продукт: Nestor 1.5.3, Windows, офлайн, CPU.
- Данные и журнал: `%LOCALAPPDATA%\Nestor` (`log.txt` — журнал работы).
- Окно: WebView2; повторный запуск поднимает уже открытое окно.
- Правки UI — один файл `nestor/web/static/index.html` (без сборки и фреймворков).
