# Nestor: бэклог юзабилити и производительности

Изначально составлен по обзору кода и UI версии 1.1.4 (коммит `d07bf11`).
Актуализирован по версии **1.3.7**: закрытые пункты отмечены, датировка
исправлена. Открытые пункты — это идеи, а не обещания; приоритет задаётся
по обратной связи от пользователей.

## Закрыто

* ~~**PUT не инвалидирует npz-кэш эмбеддингов.**~~ Исправлено: в
  `nestor/web/app.py` при изменении состава `(segment.id, segment.speaker)`
  файл `embeddings/<id>.npz` удаляется (PUT `/api/recordings/{id}` и
  `/api/recordings/{id}/speakers/merge`).
* ~~**Undo после «к спикеру…» оставляет чип-призрак.**~~ Исправлено: `undo()`
  в `index.html` восстанавливает `state.names`, `state.match`,
  `state.savedVoices` и пересобирает `state.speakers` через
  `syncSpeakersFromSegments()`.
* ~~**Поиск перерисовывает весь транскрипт на каждое нажатие.**~~ Исправлено:
  поле поиска (`#search`) получило debounce через `state.searchTimer`.
* ~~**Рельса записей пересобирается целиком каждый опрос.**~~ Исправлено:
  `loadRail()` сравнивает подпись записей и пропускает перерисовку, когда
  ничего не изменилось.

## Открыто — P1 корректность

1. **Цвет спикера меняется при вводе имени.** `speakerColor` берёт индекс из
   `state.speakers`, а `sortChips()` переставляет именованных вперёд — цвет
   «перескакивает» между чипами. Фикс: стабильный порядок по первому
   появлению в сегментах или по самой метке.

## Открыто — P2 производительность

2. **Тайминги и `log.txt`.** `on_stage` пишет `record.json` до 2,5 раз/с;
   `indent=2` добавляет 20–30 % к размеру. Первый запуск тратит 10–20 с на
   загрузку модели — в UI это выглядит как «распознавание 20 %», хотя это
   стадия `loading` → «загрузка модели».
3. **Полноволновой буфер float32** (~230 МБ/час) целиком в RAM —
   архитектурное ограничение (общий массив для диаризации, ASR и эмбеддингов),
   всерьёз не трогать.

> Пакетный расчёт эмбеддингов (`embed_segments`) как ускорение голосов ранее
> отнесён к «среднему риску»; по факту стадия «голоса» занимает ~4 % времени,
> поэтому выигрыш незначителен.

## Открыто — P3 юзабилити

4. **Фильтр по спикеру:** клик по чипу/свотчу → только его реплики + переход
   «следующая реплика спикера».
5. **Прослушать одну реплику:** двойной клик или Enter по строке играет её
   интервал.
6. **Индикатор сохранения** «сохранено / сохраняю…» у заголовка.
7. **ETA** «осталось ~N мин» из elapsed/progress (частично есть: подсказка
   карточки показывает «осталось примерно …»).
8. **Поиск по рельсе** (имя файла, «только в работе/ошибки») — частично есть
   (`#rail-search`, фильтр статуса).
9. **Подсветка найденной фразы**; Enter прыгает только вперёд.
10. **«Открыть папку данных» / «Открыть журнал»** в Помощи — есть.
11. **Клавиши J/K** — следующая/предыдущая реплика, Enter — играть реплику —
    есть.
12. **Склейка спикеров необратима** — тост с «Вернуть» (snapshot есть) — есть.
