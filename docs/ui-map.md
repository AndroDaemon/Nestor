# Карта интерфейса Nestor

Справочник названий частей UI: чтобы в задачах можно было однозначно сказать
«поправь X», и это указывало на конкретный элемент.

Весь интерфейс — один файл: `nestor/web/static/index.html` (CSS в `<style>`,
JS в `<script>`, без сборки и без фреймворков). CSS — строки 10–646,
`<script>` начинается примерно с 894. Единственный `id` — точка входа для
правок. Ниже — названия, актуальные на версию 1.3.7.

---

## 1. Крупные области (зоны экрана)

```
┌─────────────────────────────────────────────────────────────┐
│ header — топбар (шапка)                                     │
├───────────────┬─────────────────────────────────────────────┤
│ aside.rail    │ main                                        │
│ (рейл,        │  ├ #home        — стартовый экран           │
│  библиотека   │  └ #sheet-view  — экран записи (шит)        │
│  записей)     │                                             │
├───────────────┴─────────────────────────────────────────────┤
│ #dock — док плеера (только когда открыта запись)            │
└─────────────────────────────────────────────────────────────┘
   поверх всего: #modal (модалка), #toast (всплывающее уведомление)
```

| Название в задачах | Элемент | Видимость |
|---|---|---|
| **топбар** / шапка | `header` | всегда |
| **рейл** / библиотека / левая колонка | `aside.rail` | всегда |
| **главный экран** / home | `section#home` | когда запись не открыта |
| **шит** / экран записи | `section#sheet-view` | когда запись открыта |
| **док** / плеер | `div#dock` | когда запись открыта |
| **модалка** | `div#modal` | по кнопкам «От чего зависит результат» / «Приватность…» |
| **тост** | `div#toast` | 2.6 с после действия |

Переключение экранов — класс `.hidden` (`display:none !important`), прямого
роутинга нет: `openRecording()` показывает шит+док, `#btn-new` возвращает home.

## 3. Рейл (библиотека записей)

| Что | Селектор | Текст / вид |
|---|---|---|
| Заголовок | `.rail-head` | «Записи» (uppercase, 11px) |
| Кнопка «новая» | `#btn-new` (`.icon-btn`) | «+», title «Добавить файлы…» |
| Фильтр «в работе» | `#btn-rail-filter` (`.icon-btn`, `.on` при активном) | «⚑», тултип «Показать только записи в работе и с ошибкой» |
| Поиск по имени | `#rail-search` (`input.rail-search`) | placeholder «Фильтр по имени…», debounce 150 мс |
| Кнопка помощи | `#btn-help` (`.help-btn`, круг «?») | над версией; модалка помощи (две части) |
| Версия | `#app-version` (`.rail-foot`) | «Nestor 1.0.0», цвет #b9b9b9, 11px |
| Список | `#rail` (`.rail-list`) | генерируется `loadRail()` |
| Карточка записи | `.job` (+ `.job.active`, `[data-id]`) | кнопка на всю ширину |
| Имя файла в карточке | `.job .name` | обрезка в одну строку |
| Строка статуса | `.job .meta` → `.m` | только то, что требует действия: «ошибка», «остановлено · N%», «не расшифрована», «стадия · N%»; у распознанных — пусто (`.job.no-meta`), остаётся лишь точка статуса |
| Подсказка карточки | `.job[data-tip]` | многострочный хинт (в тултипе): имя, дата создания, длительность, «N спикеров · N реплик», модель, «распознано за …»; у работающих ещё «осталось примерно …» (ETA); у остальных — статус, у ошибки — текст ошибки |
| Точка статуса | `.dot.done` (зелёная) / `.dot.working` (жёлтая) / `.dot.error` (красная) / `.dot.cancelled` | 7px |
| Пустое состояние | `#rail .empty` | «Пока пусто» / «Ничего не найдено» (при фильтре) |

Клик по карточке → `openRecording(id)`. Статус в рейле обновляется опросом
`watch()` каждые 1.2 с, пока есть записи в `state.pending`. Подробности записи
(длительность, спикеры, реплики, модель, время распознавания, дата) намеренно
вынесены в хинт карточки — рейл шириной 130px обрезал их в строке под именем.
Многострочность хинта обеспечивает `white-space: pre-line` у `#tooltip`.

`loadRail()` сравнивает сигнатуру только структурных полей (`state.railKey`);
если она не изменилась, список не пересобирается — у работающих записей
точечно обновляются строка статуса и хинт (ETA), поэтому не сбрасываются
hover, фокус и прокрутка рейла.

## 4. Главный экран (`#home`)

| Что | Селектор | Текст / поведение |
|---|---|---|
| Контейнер | `.home` | max-width 620px, по центру |
| Логотип | `.home .logo` | 52px, по центру |
| Заголовок | `.home h1.sr-only` | «Расшифровать запись» — скрыт визуально (скринридеры) |
| Дропзона | `#drop` (`.drop`, при перетаскивании `.drop.over`) | клик = выбор файлов, drag&drop в любое место окна; заголовок «Перетащите аудио или видео», подсказка про локальность |
| Иконка дропзоны | `#drop .icon` | 🎧 |
| Прогресс загрузки | `#drop .title` через `dropBusy()` | на время отправки файлов: «Загрузка «имя» — N%» (пачка: «… — осталось файлов: K»), после передачи ««имя» — сохранение…»; по завершении тексты восстанавливаются |
| Скрытый input | `#file` (`type=file`, `multiple`, `hidden`) | — |
| Блок настроек | `.settings` | сетка 2 колонки; на виду — только разбивка, число говорящих и тумблер имён; остальное в `details.more` «Дополнительно» |
| Пилюли «Разбивка по говорящим» | `.settings .pill-group` → `#backend-pills` | пилюли: «Разбить по говорящим» (`auto`) / «Без разбивки» (`none`) — уходит как `backend` |
| Поле «Сколько человек в записи» | `.settings label.field` → `#speakers` | select: определить автоматически / 1…6 — уходит как `num_speakers` |
| Тумблер имён | `#vp-match` | «Подставлять знакомые имена» + счётчик `#vp-count` + кнопка «Голоса» `#btn-voices` |
| Свёрнутый блок «Дополнительно» | `details.more` на главном | внутри: «Объединять похожие голоса» `#merge-pills`, «Начинать расшифровку немедленно» `#auto-start`, «Звуковой сигнал по окончании» `#sound-done` |
| Склейка похожих голосов | `#merge-pills` (`.pill-group button.on`) | пилюли: выключено `0` / обычно `1.5` / осторожно `3` — значение уходит как `merge_min_weight`; `0` дополнительно выключает весь этап (`merge_speakers=false`). Этап выполняется в `pipeline.py` после `cluster_vectors` через `nestor/speaker_merge.py` |
| Пороги узнавания | `#vp-*-pills` внутри панели «Голоса» (`renderVoicesPanel`) | НЕ на главном экране: пилюли живут в модалке «Голоса», секция «Точность узнавания»; значения — `data-value` группы: 0.6/0.75/0.85 («Насколько уверенно узнавать»), 0/0.05/0.12 («Не путать похожие голоса», только при ≥2 голосах), 0.5/0.6/0.8 («Сверять по всей записи», только при ≥2 голосах) |
| Ссылки внизу | `.home-links` → `#btn-voices` | «Голоса»: панель с заметками (✎), датой обновления, экспортом/импортом голосов и точностью узнавания |

`.field > span` (не любой вложенный span!) — uppercase-подпись поля;
вложенные span'ы внутри подписи остаются inline (счётчик голосов).

Значения читаются в `upload()`: разбивка — `pillValue('backend-pills')`,
число говорящих — `$('speakers').value`; уходят в `POST /api/recordings`
полями `backend` и `num_speakers`. Склейка голосов — `pillValue('merge-pills')`
(`merge_min_weight` + `merge_speakers` на стороне клиента, см.
`settingsPayload()`). Пороги узнавания живут в панели «Голоса» и попадают
в `settingsPayload()`, только когда модалка открыта (`VP_SETTING_CONTROLS`);
при загрузке файла `upload()` берёт их из `serverSettings`. Импорт файла
(`POST /api/recordings/import`) берёт те же значения из `settings.json`.

Загрузка идёт через `postRecording()` (XMLHttpRequest, а не fetch) —
только XHR даёт `upload.onprogress`. Серверная сторона копирует файл
на диск в фоновом потоке (`asyncio.to_thread`), поэтому цикл событий
жив во время загрузки: опрос рейла, стоп-кнопка и остальные запросы
не застревают.

| — разделить | `.tools button` (3-я) | «разделить» → `splitSegment()`: рез по ближайшей границе слова (`snapCutToWord()`), время — по доле текста; Ctrl+Enter в тексте — то же без мыши; кнопки панели гасят `mousedown`, чтобы не терять каретку |

Цвета спикеров: классы `.sp-0`…`.sp-11` (12 цветов, дальше циклически) и
`PALETTE` в JS для волны/чипов. Слот цвета закрепляется за спикером при первом
появлении (`speakerIndex()`/`state.colorIndex`) и не «плывёт» при пересортировке
чипов (`sortChips` выносит именованных вперёд).

Реплика со совпадением поиска получает класс `.seg.hit` (розовая подсветка),
совпавшие фрагменты обёрнуты в `<mark>` (`highlightHTML()`). Класс `.seg.active`
ставит `setActiveSegmentId()` — рамка текущей воспроизводимой реплики.

## 9. JS-функции, которые рисуют UI

| Функция | Что перерисовывает |
|---|---|
| `loadRail()` | рейл; в карточке — короткий статус на виду, подробности в `data-tip` (`fmtDateTime()` + `fmt()`); пропускает пересборку при неизменной сигнатуре (`state.railKey`), точечно обновляет работающие карточки; фильтры `state.railOnly` / `state.railQuery` |
| `railMeta(rec)` / `railHint(rec)` / `fmtEta(elapsed, progress)` | короткий статус, многострочный хинт и «осталось примерно …» для работающих записей |
| `openRecording(id)` | переключение на шит, шапка, аудио, все блоки |
| `renderChips()` | чипы спикеров (класс `.filter` у выбранного цветом) |
| `renderFilterBar()` | `#filter-bar`: активный фильтр по спикеру + «показать всех» |
| `renderSegments()` | список реплик (с учётом `filterSpeaker`) + подсветка совпадений `<mark>` + счётчик поиска |
| `syncSpeakersFromSegments()` | пересобирает `state.speakers` по сегментам, чистит имена/`match`/`savedVoices` опустевших меток |
| `speakerIndex(id)` / `speakerColor(id)` | слот цвета закрепляется за спикером при первом появлении (не «плывёт» при `sortChips`) |
| `setSpeakerFilter(id)` | фильтр «только этот спикер» (повторный клик / `Esc` — сброс) |
| `highlightHTML(text, query)` / `plural(n,…)` | обёртка совпадений в `<mark>`; русское склонение для счётчика |

Сохранение голоса на сервере (`_voiceprint_vector` в app.py): валидный кэш
`embeddings/<id>.npz` (метки кэша покрывают все длинные метки записи) — готовый
вектор; иначе decode аудио + эмбеддинг **только сегментов запрошенного
спикера** (частичный результат в кэш не пишется); блокирующая работа — в
threadpool (`run_in_threadpool`), event loop свободен.

`state` — всё состояние UI: `recordings`, `current`, `speakers`, `names`,
`match`, `savedVoices`, `dirty`, `follow`, `peaks`, `pending`, `caret`, `undo`,
`view` (окно зума таймлайна), `saveTimer`, `searchCursor`, `searchTimer`,
`filterSpeaker`, `playUntil`, `colorIndex`, `nextColor`.

Дубли имён спикеров: чип с именем, которое встречается ещё у кого-то,
получает класс `.dup` (жёлтая кромка + точка) и тултип «можно склеить».

## 10. Как ссылаться в задачах

Достаточно «зона → элемент → подпись». Примеры:

- «В **шите**, в **панели действий реплики**, кнопка **„склеить“** должна быть disabled на последней реплике»
- «В **доке**, рядом с **`#t-pos`**, показывай остаток времени»
- «В **топбаре**, **меню выгрузки**: добавь пункт **PDF**»
- «На **главном экране**, в блоке **настроек**, поле **„Сколько человек в записи“** — добавь 7 и 8»
- «В **рейле**, **карточка записи**: показывай прогресс обработки вместо „обработка…“»

Если элемент без `id` (например, кнопки внутри `.tools` или бейджи `#rec-sub`),
указывай зону и подпись — я найду по тексту/индексу.

## 12. Диаризация и отмена (поведение после багфикса 2ca8149)

- Диаризация sherpa-onnx прерывается колбэком прогресса: правый клик →
  «Остановить обработку» и «Удалить запись» действуют в течение секунды,
  а не после завершения всего прогона.
- PUT правок во время queued/running → 409 «Идёт обработка — правки сейчас
  сохранить нельзя»; UI оставляет правки в памяти и предупреждает тостом.
- Удаление идемпотентно: дочищает остатки прерванного удаления, снимает
  peaks-файл и кэш эмбеддингов `embeddings/<id>.npz`; при заблокированных
  файлах — 409 «Часть файлов занята…».
- Спикер-диалог повторного прохода не содержит поля модели (только число
  спикеров и подстановка имён); prefilled из `job_settings`.
