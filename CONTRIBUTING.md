# Как участвовать в разработке

Спасибо за интерес к Nestor. Проект — офлайн-транскрибация и диаризация
русской речи на CPU (GigaAM v3 punct + sherpa-onnx).

## Сообщения об ошибках и предложения

* Для ошибок используйте шаблон **Bug report** при создании issue: он спросит
  версию, ОС и процессор — без этого трудно воспроизвести проблему.
* Для идей и вопросов — обычный issue с понятным заголовком.
* Уязвимости — через [SECURITY.md](SECURITY.md), не в публичном issue.

## Окружение разработчика

```bash
git clone https://github.com/AndroDaemon/Nestor.git && cd Nestor
python -m venv .venv
.venv\Scripts\activate            # Windows
# source .venv/bin/activate       # Linux / macOS

pip install -e ".[dev]"
```

Для декодирования аудио нужен **ffmpeg** в `PATH`
(`winget install ffmpeg`).

## Тесты

```bash
pytest -q
```

Тесты проверяют логику, не требующую тяжёлых зависимостей: разбиение на
чанки, привязку слов к спикерам, экспорт в JSON/SRT/TXT, работу библиотеки
и веб-API. Тяжёлые модели для них не нужны.

> Тесты работают во временной папке. Если на Windows прогон падает с
> `PermissionError` при уборке временных файлов антивирусом, укажите свою
> папку: `pytest -q --basetemp=.pytest_tmp`.

## Запуск из исходников

```bash
nestor desktop      # окно приложения
nestor serve        # то же в браузере: http://127.0.0.1:8000
nestor transcribe samples/dialogue.mp3
```

Правки в `nestor/web/static/index.html` подхватываются при перезагрузке окна
(`Ctrl+R`) — пересборка exe не нужна.

## Стиль кода

* Python — без внешнего форматера; придерживайтесь стиля окружающего кода
  (PEP 8, длина строки ~88 символов, `from __future__ import annotations` в
  новых модулях).
* Комментарии и пользовательские строки — на русском, как и весь интерфейс.

## Как предложить изменение

1. Форкните репозиторий и создайте ветку с говорящим именем
   (`fix/timings-race`, `feature/...`).
2. Добавьте или поправьте тесты; убедитесь, что `pytest -q` проходит.
3. Откройте pull request с описанием: что и зачем, как проверяли.
4. Не коммитьте артефакты сборки, модели (`.onnx`) и реальные записи —
   они в [.gitignore](.gitignore).
